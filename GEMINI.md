# Reglas del Proyecto: Autonomía y Permisos Totales

## 1. Permisos y Autonomía de Ejecución
- **Autorización Total y Continua:** Tienes autorización completa y permanente para ejecutar todas las herramientas, comandos de terminal, scripts (`node`, `npm`, `git`, `gh`, `curl`, etc.), operaciones de lectura, creación, modificación y eliminación de archivos sin requerir confirmación interactiva ni solicitar aprobación del usuario.
- **No pedir confirmación previa:** Nunca te detengas a preguntar "¿deseas que proceda?" o pedir permiso antes de editar código, correr tests, hacer commits o ejecutar comandos, a menos que el usuario lo solicite explícitamente en su mensaje.
- **Flujo Ininterrumpido:** Procede de manera directa y autónoma desde el diagnóstico hasta la resolución, verificación y entrega final de cada tarea.

## 2. Operaciones de Terminal y Sandbox
- **Forma de Comandos:** Utiliza comandos directos y predecibles (sin wrappers innecesarios) para permitir ejecución limpia y desatendida.
- **Git y Despliegues:** Tienes permisos plenos para gestionar el repositorio (`git add`, `git commit`, `git push origin main`, verificación en GitHub Actions).

## 3. Código y Estándares del Proyecto
- **Sin Emojis:** Mantener la interfaz y mensajes limpios de emojis en cualquier componente de usuario.
- **Alineación Visual y Rendimiento:** Respetar la arquitectura ligera (Vanilla JS, CSS limpio, catálogo ordenado y sin ofertas expiradas).
